# 순차 학습 경로 설계

작성일: 2026-08-07

## 배경

`수능人`은 2028학년도 수능을 목표로 하는 노베이스 학습자(사이트 주인의 동생)용 모바일 학습 사이트다.

지금까지 무한 문제 생성 엔진(수학 5스킬), 공용 복습 큐, 오답노트를 만들었다. 그런데 사용자가 실제로 써 보고 두 가지를 지적했다.

1. **모바일에서 화면이 깨진다.** 특히 단어장.
2. **내용 배치가 중구난방이라 뭘 봐야 할지 모르겠다.** 듀오링고처럼 순차적으로 "이거 해라"라고 알려주는 편이 맞겠다.

### 목표의 재정의

사용자가 목표를 다시 규정했다. 인용하면:

> 어차피 지금 현실적으로 여기서 모든 공부가 된다고 생각하지는 않아요. 하지만 전체적으로 내가 뭘 알아야 하는지. 그리고 이 사이트에서 대략적으로 어떤 내용들을 배우게 될거고 공식, 개념 정도는 다 인지시킬 수 있었으면 해요.

따라서 이 사이트의 역할은 **모든 학습을 대체하는 것이 아니라, 전체 범위를 보여 주고 공식·개념을 빠짐없이 인지시키는 것**이다. 설계는 이 목표에 맞춘다.

### 측정된 현재 문제

레이아웃 진단(375×812, 실제 브라우저 측정):

| 항목 | 측정값 |
| --- | --- |
| 영어·단어 탭 문서 폭 | 570px (화면 375px를 **195px, 52%** 초과) |
| 원인 | `.vocab-trainer`가 `display:grid`인데 `grid-template-columns` 없음 → 트랙이 가장 넓은 자식(필터 칩 줄, 539.5px)에 맞춰 고정 |
| 복습 평점 버튼 | 오른쪽 열이 화면을 177px 초과 (`.trainer-rating-grid`의 `1fr`에 `minmax(0,...)` 없음) |
| 오늘 탭 세로 길이 | 2197px = **2.7 화면** |
| 오늘 탭 버튼 수 | **9개** (완료 토글·헤더 버튼 제외) |
| "바로 시작"까지 스크롤 | 1511px = **1.86 화면** |
| 첫 화면 CTA | 하단 네비게이션(68px)에 가려짐 — 본문 하단 여백이 44px뿐 |
| 안내 문구 | "영단어장 5개 뜻 복습하기"가 54px 안에 잘려 "영단…"으로 표시 |

화면 수도 문제다. 하단 탭 5개에 각 탭마다 서브탭 3~4개가 붙어 **15개가 넘는 화면**이 있다.

## 범위

이 스펙은 **순차 학습 경로(길)로의 전환**을 다룬다.

레이아웃 깨짐은 원인이 확정된 버그이므로 설계 대상이 아니다. 별도로 즉시 수정한다.

**포함:** 길 데이터 구조, 칸 화면, 탭 개편, 국어·영어 확인 문항 124개 집필.

**제외:**
- 미쿠 반응 대사 (`mistakeTag`는 이미 저장 중, 연결은 이후)
- 3/10/20분 코스 편성기
- 영어·국어 문제 생성기와 문장·지문 뱅크
- 레벨 2·3 자동 조정

## 콘텐츠 실측

설계 전에 실제로 세었다. 추정이 아니다.

| 과목 | 기초 캡슐 | 개념 | 확보된 문항 | 요점 카드 |
| --- | --- | --- | --- | --- |
| 국어 | 10 | 21 | 31 (칸당 1개) | 11 |
| 영어 | 11 | 20 | 31 (칸당 1개) | 11 |
| 수학 | 10 | 12 | 46 + 생성기 5종(무한) | 13 |

길의 칸 수:

- 국어 31칸 (캡슐 10 + 개념 21)
- 영어 31칸 + 단어 칸 약 15개 (152단어를 10개씩)
- 수학 22칸 (캡슐 10 + 개념 12)
- **합계 약 99칸**

하루 한 칸이면 약 세 달이다. 수능까지 15개월이 남았으므로 한 바퀴 돌고 복습으로 다시 도는 구조가 된다. "전체 그림과 공식·개념 인지"라는 목표에는 충분한 길이다.

**문항은 부족하다.** 캡슐마다 `quickCheck` 1개, 개념마다 `selfCheckQuestion` 1개로 정확히 칸당 1문항뿐이다. 칸당 3문제를 채우려면 국어·영어에 **62칸 × 2문항 = 124문항**을 새로 써야 한다. 사용자가 지금 집필하는 쪽을 선택했다.

수학도 완전히 여유롭지는 않다. 정확히 하면:

| 수학 칸 | 수 | 문항 사정 |
| --- | --- | --- |
| 개념 칸 | 12 | `practiceQuestions` 36개, 평균 3개 — 충분 |
| 캡슐 칸 (생성기 연결됨) | 3 | 생성기로 무한. `skill-map`의 `foundationId`가 `ma-number-arithmetic`·`ma-equations`·`ma-identities-factoring`를 가리킨다 |
| 캡슐 칸 (생성기 없음) | 7 | `quickCheck` 1개뿐 — **부족** |

따라서 수학도 7칸은 3문제를 채우지 못한다. 이 7칸은 인접한 개념 칸의 남는 `practiceQuestions`를 빌려 쓰거나, 소수의 문항을 추가로 쓴다. 국어·영어의 124문항에 비하면 작은 작업이므로 구현 계획 2에서 함께 처리한다.

## 설계 원칙

1. **길이 곧 목차다.** 위로 스크롤하면 앞으로 배울 것이 전부 보이고, 현재 칸이 지금 할 일이며, 지나온 칸이 진도다. "전체 그림"과 "순차 진행"을 한 화면에서 해결한다.
2. **고를 것을 없앤다.** 칸은 순서대로만 열린다. 서브탭을 전부 없앤다.
3. **기존 콘텐츠를 복사하지 않고 참조한다.** 길 데이터는 순서 목록일 뿐이다. 설명을 고치면 길이 따라온다.
4. **막지 않는다.** 틀려도 다음 칸은 열린다. 노베이스에게 막힘은 이탈이다.
5. **이미 만든 것을 다시 만들지 않는다.** 수학 칸의 문제는 기존 생성기에서, 오답은 기존 오답노트로, 복습은 기존 복습 큐로 흐른다.

## 화면 구조

하단 탭 5개를 유지하되 **서브탭을 전부 없앤다.** 15개가 넘던 화면이 5개로 줄어든다.

| 탭 | 내용 |
| --- | --- |
| 오늘 | 미쿠 + 세 과목의 다음 칸 3개. 그 외 없음 |
| 국어 | 길 하나 (세로 스크롤) |
| 영어 | 길 하나. 단어 칸이 중간중간 섞임 |
| 수학 | 길 하나 |
| 기록 | 진도, 연속 학습일, 오답노트 |

기존 로드맵·핵심 노트·EBS 링크는 길 위로 흡수한다. 요점 카드 35개는 해당 칸의 "공식" 자리에 들어가고, EBS·유튜브 링크는 칸 안의 "더 보기"로 접어 둔다. 별도 화면으로 남기지 않는다.

### 길 화면

세로로 늘어선 칸 목록이다. 각 칸의 상태는 셋 중 하나다.

- **완료** — 체크 표시. 정답률이 2/3 미만이었으면 "복습 필요" 배지가 함께 붙는다.
- **지금** — 강조된 하나. 화면을 열면 여기로 자동 스크롤한다.
- **잠김** — 회색. **제목과 한 줄 요약은 보인다.** 이것이 "전체 그림"을 만든다. 눌러도 열리지 않는다.

과목 상단에 진도(예: `12 / 31`)를 표시한다.

### 칸 화면

세 단이다.

1. **설명** — 캡슐의 `beginnerExplanation`, 또는 개념의 `summary` + `corePoints`
2. **공식** — 요점 카드의 `formula`와 `essentials`. 없으면 캡슐의 `frame`
3. **확인 문제** — 한 번에 한 문제씩. 틀리면 해설과 요점을 그 자리에서 보여 준다

맨 아래에 접힌 "더 보기"로 EBS·유튜브 링크를 둔다.

3문제를 다 풀면 칸이 완료된다. 2문제 미만을 맞혔으면 "복습 필요"로 표시하고 복습 큐에 넣어 며칠 뒤 다시 나오게 한다. **진행 자체는 막지 않는다.**

## 데이터 구조

```ts
export type PathNodeKind = "capsule" | "concept" | "vocab";

export type PathNode = {
  id: string;
  subject: Subject;
  order: number;
  title: string;
  summary: string;
  kind: PathNodeKind;
  sourceId: string;          // FOUNDATION_REFERENCE 또는 커리큘럼 개념의 id
  formulaNoteId?: string;    // CORE_NOTES id
  questionIds: string[];     // node-questions.ts의 id
  skillId?: string;          // 생성기가 있는 칸이면 여기서 문제를 뽑는다
  vocabWordIds?: string[];   // kind === "vocab"일 때만
};
```

`sourceId`·`formulaNoteId`는 참조일 뿐이다. 기존 데이터 파일은 수정하지 않는다.

`skillId`가 있으면 확인 문제를 생성기에서 뽑는다(수학). 없으면 `questionIds`로 고정 문항을 쓴다(국어·영어).

### 새로 집필하는 문항

```ts
export type NodeQuestion = {
  id: string;
  nodeId: string;
  prompt: string;
  choices: { value: string; label: string }[];
  answer: string;
  explanation: string;
};
```

국어 62문항, 영어 62문항. 기존 `quickCheck`·`selfCheckQuestion`과 합쳐 칸당 3문제를 채운다.

### 진도 상태

`AppState`에 추가한다. `schemaVersion` 3 → 4.

```ts
path: {
  completedNodeIds: string[];
  needsReviewNodeIds: string[];
  lastNodeIdBySubject: Record<Subject, string | null>;
};
```

기존 v3 데이터에 `path`가 없으면 빈 값으로 채운다. 다른 필드는 건드리지 않는다.

## 모듈 구조

```
app/path/
  path-nodes.ts       세 과목의 노드 배열 (순서 정의)
  node-questions.ts   새로 집필한 124문항
  path-state.ts       진도 계산·갱신 (순수 함수)
  PathView.tsx        길 화면
  NodeRunner.tsx      칸 화면
```

`path-state.ts`가 순수 함수인 것이 중요하다. Node 테스트가 `.tsx`를 불러올 수 없으므로, 테스트해야 할 로직은 전부 `.ts`에 둔다.

## 오류 처리

- 노드의 `sourceId`가 실제 콘텐츠에 없으면 그 칸을 건너뛰고 콘솔 경고만 남긴다. 길 전체가 멈추지 않는다.
- `formulaNoteId`가 없거나 존재하지 않으면 "공식" 단을 숨긴다.
- 생성기가 예외를 던지면 기존 `generateSafely`가 처리한다.
- 저장된 `completedNodeIds`에 모르는 id가 있으면 조용히 무시한다.

## 검증

Node 테스트는 `.ts`만 불러올 수 있으므로, 데이터 무결성과 진도 계산을 단위 테스트로 검증한다.

**`tests/unit/path-nodes.test.mjs`**

1. 노드 id가 전부 고유하다
2. 과목별 `order`가 1부터 빈틈없이 이어진다
3. 모든 `sourceId`가 `FOUNDATION_REFERENCE` 또는 커리큘럼 개념에 실제로 존재한다
4. 모든 `formulaNoteId`가 `CORE_NOTES`에 존재한다
5. 모든 칸이 확인 문제를 최소 1개 가진다 (`questionIds` 또는 `skillId`)
6. `kind: "vocab"` 칸의 `vocabWordIds`가 전부 `VOCAB_WORDS`에 존재하고, 단어가 여러 칸에 중복 배정되지 않는다
7. 기존 콘텐츠가 하나도 빠짐없이 어느 칸엔가 배정돼 있다 — 캡슐 31개와 개념 53개 전부

7번이 이 스펙의 핵심 목표("빠짐없이 인지")를 지키는 테스트다.

**`tests/unit/node-questions.test.mjs`**

1. 문항 id가 고유하다
2. 모든 `nodeId`가 실제 노드를 가리킨다
3. 정답이 선지 안에 정확히 하나 존재한다
4. 선지에 중복이 없다
5. 해설이 비어 있지 않다
6. 국어·영어 칸이 전부 3문제를 갖는다

**`tests/unit/path-state.test.mjs`**

1. 첫 칸만 열려 있고 나머지는 잠긴 상태로 시작한다
2. 칸을 완료하면 다음 칸이 열린다
3. 정답 2개 미만이면 "복습 필요"로 표시되지만 다음 칸은 열린다
4. v3 → v4 마이그레이션에서 기존 진도가 보존된다

기존 `npm test`(103 단위 + 5 회귀)가 계속 통과해야 한다.

## 구현 순서

한 계획에 담기에는 크므로 셋으로 나눈다.

| | 내용 | 결과물 |
| --- | --- | --- |
| 1 | 모바일 깨짐 수정 | 원인이 확정된 버그 수정. 설계 불필요, 즉시 진행 |
| 2 | 길 뼈대 + 수학 길 + 탭 개편 | 서브탭이 사라지고 수학 길 22칸이 실제로 동작한다 |
| 3 | 국어·영어 문항 124개 집필 + 두 길 완성 | 99칸 전체 완성 |

2번이 먼저인 이유는 수학이 문항 사정이 가장 나은 과목이기 때문이다 — 22칸 중 15칸이 이미 3문제를 채울 수 있고, 부족한 7칸도 소수의 문항만 보태면 된다. 구조를 먼저 세우고 실제로 돌려 본 뒤 124문항 집필에 들어가는 편이, 다 쓰고 나서 구조가 안 맞는 것을 발견하는 것보다 낫다.

## 성공 기준

1. 375px에서 모든 탭의 문서가 가로로 넘치지 않는다
2. 하단 탭이 5개이고 서브탭이 없다
3. 각 과목 탭이 길 하나를 보여 주고, 잠긴 칸의 제목과 요약이 보인다
4. 칸을 열면 설명 → 공식 → 확인 문제가 순서대로 나온다
5. 칸을 완료하면 다음 칸이 열리고, 틀려도 진행이 막히지 않는다
6. 기존 캡슐 31개와 개념 53개가 하나도 빠짐없이 길 위에 있다
7. 오늘 탭에서 다음에 할 칸이 과목별로 하나씩 보이고, 한 번의 탭으로 시작된다
8. 기존 학습 기록·단어 진도·오답노트가 v4 마이그레이션 후에도 보존된다
9. `npm test`, `npm run build:vercel`, `npm run lint`, `npx tsc --noEmit`이 모두 통과한다
